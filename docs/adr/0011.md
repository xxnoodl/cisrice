# ADR 0011: Local identity and scoped database access

Status: Accepted for Milestone 1.

## Context
Business data must be protected before discovery or domain jobs are introduced.

## Decision
Use operator-only CLI provisioning and Argon2id (19 MiB, two iterations, parallelism
one). Use random opaque eight-hour sessions with only SHA-256 digests in PostgreSQL.
Return a session-bound HMAC CSRF token through authenticated JSON. Cookies are
HttpOnly, SameSite=Strict, host-only; Secure is configurable for TLS. Default access
is localhost HTTP or an SSH tunnel.

Require trusted Host, exact Origin on writes, CSRF on authenticated writes, bounded
JSON and Redis-backed atomic rate limits. Redis failure blocks login/writes.
Validation errors exclude input values. Transactions finish before success responses.

Workspace owner/member roles precede explicit brand and account editor/viewer grants.
Owners inherit full workspace access. Members need workspace and brand access;
accounts need another explicit grant. Composite foreign keys prevent cross-workspace
parent references. Revocation cannot resurrect prior account grants.

Migration credentials stay separate from runtime. The migration runner provisions
cisrice_app without superuser, database/role creation or schema management. Audit
rows are append-only for the runtime role; database operators remain trusted.

## Alternatives
JWT invalidation adds complexity. Public initial registration creates a setup race.
Redis-only sessions lose authoritative state. Frontend filters cannot enforce scope.
Superuser runtime credentials have excessive blast radius. An external identity
provider adds deployment complexity.

## Consequences
No default password, public signup, invitations or self-service reset. Local operators
create users interactively. Account registration is separate from OAuth; provider
passwords/tokens are not accepted or stored. Add a vault with a key outside the DB
before storing credentials. UI lists show up to 200 portfolio records; paginated API
access is available for larger portfolios.

## Revisit conditions
Hosted deployment, invitations, idle-session controls or OAuth credential storage.
Remote access remains localhost plus SSH until explicit TLS configuration.

Authenticated logout retains Origin/CSRF protection but bypasses the Redis rate
bucket so the authoritative PostgreSQL session can be revoked during a Redis outage.
Business writes and login continue to fail closed. FastAPI >=0.121 is required for
function-scoped transaction dependencies that finish before the response is sent.
