# ADR 0013: Durable jobs before acquisition workers

Context: Redis and Celery cannot be the sole authoritative record of acquisition.
The repository forbids business tasks until durable state, idempotency and
cancellation have tests.

Decision: PostgreSQL owns queued/running/retry/terminal states, an actor and brand
scope, versioned payload, correlation and idempotency keys, attempt budgets,
cancellation requests and expiring worker leases. A PostgreSQL polling dispatcher
reissues unclaimed messages. Redis carries only a job ID. Claims and completion are
serialized and fenced by a random lease token. Workers recheck the originating
actor's current authorization before work and before registering outputs.

Duplicate delivery returns without a second active claim. Expired leases allow
bounded retry; an obsolete worker cannot commit completion. Cancellation is
cooperative; a cancelled or obsolete job cannot register a successful output.
Publishing will require a separate remote-state reconciliation contract.

Alternatives: Celery result backend alone (not durable application ownership),
exactly-once execution claims (unsupported), unbounded retries (unsafe).
Consequences: at-least-once execution; handlers must be idempotent and use unique
staging locations. Dispatcher and lease monitoring are required for recovery.
Revisit when distributed resource scheduling or publication is introduced.

Implementation verification: durable lifecycle tests passed before Celery task
registration. Public JobLifecycle returns immutable JobLease contracts; acquisition
does not mutate operations entities. Job rows serve as the transactional dispatch
outbox, retried until claimed rather than trusting Redis publication as completion.
Standalone dispatchers explicitly load referenced identity table metadata.
