# ADR 0014: Rights-reviewed acquisition and immutable canonical objects

Context: a public URL does not establish redistribution rights. Extractors can
follow redirects and contact hosts other than the source URL.

Decision: require a recorded human rights decision before acquisition. Preserve
ownership/license/permission evidence, attribution and restrictions independently
of research approval. Workers recheck the decision and originating actor at claim
and completion. Rights may be revoked; revocation blocks future acquisition and
reuse, without silently destroying retained source media.

Use per-lease staging directories, bounded direct HTTPS transfers and ffprobe plus
FFmpeg validation of local video containers. Canonical objects are SHA-256 addressed;
only brand-scoped references are exposed. Never overwrite a canonical object or
delete referenced media. Explicit cross-brand reuse requires source authorization
and a separate destination rights decision.

yt-dlp is an optional metadata/format resolver behind a local validating proxy.
Only single direct HTTPS video formats are eligible initially; no authenticated,
DRM, playlist, live-stream, segmented or external-downloader path is supported.
Extracted URLs are ephemeral and never logged. Native bounded download code handles
the selected format, avoiding ffmpeg network input and uncontrolled redirects.

Alternatives: unrestricted extractor subprocess (SSRF risk), considering discovery
approval a license (invalid), mutable title-based media paths (deduplication risk).
Consequences: some platforms/formats will be unavailable; local CPU validation and
disk quotas may reject long or large files. Publishing performs independent checks
in its later milestone. Revisit with tested platform-specific acquisition adapters.

Runtime database permissions make media objects and brand links append-only.
Temporary-file retention is operator-triggered, dry-run by default, with pre-purge
and completion audit records. Canonical objects are always retained.
The restricted resolver uses system CAs (no-certifi compatibility option), verified
against an owned TLS fixture. Unknown format codec labels are deferred to local
ffprobe/FFmpeg rather than rejected prematurely by the metadata format selector.

Geographic bypass is explicitly disabled; extractor defaults cannot override source access restrictions.
